# 听风执牌 v7：决策侧接口

执牌端识别画面、维护本局历史、点击并核对结果。引擎接收牌和事件，返回动作；执行动作不需要引擎提供坐标。四人场使用听风 v96-hp，三人场使用听元 v10。

## 一次请求

执牌端启动所选档位的 exe，传入 `--analyze`。stdin / stdout 使用 UTF-8 JSON Lines，每条消息占一行，写出后应立即刷新。stdout 只写协议；搜索诊断写 stderr。普通决策返回后 stdin 关闭；两阶段鸣牌期间进程和 stdin 保持打开。

下面是一个完整的四人场请求。庄家起手十三张，摸七条，可打牌。引擎可以返回一行 `{"response":"PLAY T7"}`。

```json
{"requests":[{"state":"0 0 0","validact":null},{"handTiles":"1 W4 W4 B3 B5 B6 B7 T2 T4 T4 T6 T6 T9 Z6","doraIndicators":"Z1","validact":null},{"state":"2 T7","validact":"PLAY"}],"responses":["PASS","PASS"],"data":null,"match_context":{"schema":1,"scores":[25000,25000,25000,25000],"hand_index":1,"honba":0,"riichi_sticks":0,"remaining_scheduled_hands":4,"is_last_scheduled_hand":false,"tie_priority":[0,1,2,3]},"call_search":{"schema":1,"id":"example-1","mode":"continue_after_call"}}
```

`requests` 按发生顺序排列，最后一项是本次操作窗口。`responses` 对应此前的请求，比 `requests` 少一项。历史中的 `PASS` 也用作没有本方操作的占位符。用公开事件重放局面；不要把历史回答和其后确认的公开动作各执行一遍。

| 输入 | 含义 |
| --- | --- |
| `0 <自风座位> <场风>` | 东、南、西、北从 0 起编号；三人场只有座位 0、1、2。 |
| `handTiles: "1 ..."` | 设置当前暗手。首次为起手牌；后来带 `source:"verified-current-hand"` 的记录校正暗手，不代表重新开局。 |
| `2 <牌>` | 本方摸到这张牌。对手的未知摸牌记作 `3 <座位> DRAW`。 |
| `3 <座位> PLAY/LIZHI <牌>` | 该玩家弃牌或以该牌宣言立直。可附带手切／摸切证据。 |
| `3 <座位> CHI/PENG <叫牌> <手中牌1> <手中牌2> <弃牌>` | 已完成的吃碰及其后弃牌；鸣牌来源是被叫走的那次弃牌。三人场不能吃。 |
| `3 <座位> GANG/ANGANG/BUGANG ...`；`3 <座位> KITA Z4` | 明杠、暗杠、加杠；三人场另有拔北。这些动作本身不等于补摸。 |

牌码为 W 万、B 筒、T 条，Z1–Z7 为东南西北白发中。数牌的 0 是赤五，传递和移除实体牌时须与普通五区分。`doraIndicators` 是空格分隔的**指示牌**。三人场提供可靠余牌读数时，当前事件还带 `remaining`。`match_context` 提供点数、局序、本场、供托、剩余预定局数和同分优先顺序，点数按座位顺序排列。

可选的 `opponent_hand_constraints` 使用 `schema:2,time_scope:"current"`：每个约束指定 `tile` 和 `any_of:[{seat,minimum_count},...]`。一个约束内只要求**至少一家**达到其下限；不同约束同时成立。每次以本次提供的完整约束为准，不再叠加旧请求中的下限。

## 选择和确认动作

`validact` 用逗号分隔当前可用动作。普通弃牌返回 `PLAY <牌>`；立直返回 `LIZHI <弃牌>`；自摸和荣和窗口分别列出 `TSUMO` 和 `RONG`，选择和牌均返回 `HU`。跳过返回 `PASS`；不能在只有 `PLAY` 的窗口返回 `PASS`。三人场拔北返回 `KITA Z4`。

吃碰采用两阶段响应，两个阶段共用一个请求 ID：

1. 引擎先返回 `{"phase":"call","id":"example-1","revision":0,"response":"PENG Z6 Z6 Z6"}`。执牌端点击碰和所选组合；引擎继续计算弃牌。
2. 执牌端核对实际组合后，通过 stdin 发送 `type:"call_observed"`，包含 `schema:1`、相同的 `id` 和 `revision`，以及实际组合 `response`、碰后暗手 `hand_tiles`、可弃牌 `legal_discards`。
3. 实际组合不同或可弃牌发生变化时，执牌端改发 `type:"call_corrected"` 并递增 `revision`。引擎按新证据计算。若鸣牌被抢，执牌端取消会话，不执行该分支的弃牌。
4. 引擎返回 `{"phase":"discard","id":"example-1","revision":0,"response":"PLAY B6"}`。执牌端只采用当前 ID、当前修订且实际合法的结果。`elapsed_ms` 可报告本阶段用时。

**三人场的特殊恢复：** 如果引擎决定跳过，但画面证实本方已碰且还没弃牌，执牌端可发 `{"state":"3 2 PENG Z6 Z6 Z6","observedCallBeforeDiscard":true,"validact":"PLAY","remaining":42}`。引擎应从暗手移出两张发，登记来自上一次弃牌的碰，保持牌山 42，直接选择合法弃牌。此处没有摸牌。确认弃牌后，后续历史使用包含实际弃牌的标准 PENG 事件。

## 决策行和搜索统计

stderr 的 `type:"decision_telemetry"` 用 `response` 匹配本次动作；阶段响应也可内嵌 `telemetry`。`exit_reason`、`nodes`、`layer_completion.progress/shape` 用于显示结束原因、节点数、向听／改良层进度。完成层数可为小数，不要截断。

在 `retention_decision:true` 的最终记录中，`final_action` 指定结果，`candidates` 内相应的 `selected:true` 行提供 `off`、`win`、`current_p_ron` 和 `policy`。概率用 0–1；缺少估计时不要填 0。终端显示的“预期价值提升”是与上次可比进攻评分的差，首条以 0 为基准。役满机会取本阶段最终遥测的 `selected_yakuman_preference` 和 `selected_yakuman_names`；只有标记为真时，才在放铳率后显示役名。
